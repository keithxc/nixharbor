# 栖港 · NixHarbor 产品计划书

讨论稿 · 2026-11-06

栖港面向全球第一次使用 NixOS 的桌面用户。一个人如果会在 iPad 上找应用、点安装、打开使用，就应该能用同样的经验管理这台电脑。软件商店是第一个入口。长期目标是让用户用图形界面完成从首次安装系统到日常维护、更新和恢复的全过程。

首轮建议以 x86_64 的 NixOS KDE 桌面为验证对象，同时设计简体中文和英文两套界面。中国大陆优先验证下载和常用软件体验。使用中文、身处大陆、想装微信是三个独立的选择：在海外用中文的人可以走全球下载源，在大陆用英文的人也可以走境内下载源。

## 用户第一次打开商店

小林刚装好系统，想用微信收一份文件。他在商店里输入“微信”或“WeChat”，看到微信的名称、发布者、图标和“安装”。点一次后，商店在同一张卡片上显示下载进度，完成后按钮变成“打开”。此时应用菜单里也有微信，重启后仍能找到。微信自己的扫码登录在应用里完成。

| 用户想做什么 | 界面应怎样回应 |
| --- | --- |
| 找软件 | 首页可以搜索，也可按通讯、办公、影音等类别浏览。同一款软件的中文名、英文名和常用别名都能搜到。 |
| 安装 | 普通安装只点一次。商店自动匹配电脑和下载位置。需要同意发布者条款或系统授权时，才说明原因并请求确认。 |
| 等待或中断下载 | 展示进度，允许取消。来源超时自动换源。断网后保留任务，恢复网络可重试。磁盘不足显示还差多少空间。 |
| 更新 | “我的应用”集中列出可用更新。更新失败时，原有版本仍能打开。 |
| 卸载 | 从“我的应用”移除程序，默认保留个人数据。清除聊天文件等个人数据需要单独操作。 |

首批应用选微信、QQ 和 VLC。微信、QQ 验证厂商发布的软件在大陆桌面上的真实体验，VLC 用于验证全球用户获取开源应用的路径。上架门槛是用户可实际使用。以微信、QQ 为例，要能打开、登录、中文输入、收发一条消息及文件；VLC 要能从文件管理器打开并播放本地视频。具体版本和受支持功能随上架记录公布。

## 商店如何使用 GitHub、Gitee 和国内下载地址

把**应用目录**和**安装包**分开维护。目录回答“哪个版本适合这台电脑、去哪里拿、如何验证和安装”。安装包可以留在厂商官网、上游 GitHub/Gitee Release，或明确允许分发的镜像站。用户点“安装”时由商店读取已审核目录，无需自己登录代码托管平台、挑架构或复制链接。

1. **收录。** 维护者或社区提交上游主页、发布者身份、版本、架构、候选下载地址、许可和适配方法。自动采集只生成待审核记录。收录 GitHub 或 Gitee 项目时先确认仓库属于上游或其认可的发布方。
2. **验证。** 为每种架构下载候选包，固定大小和 SHA-256，核对上游签名（如有），并在干净的 NixOS 桌面验证安装及启动。相同文件的镜像必须匹配同一摘要。不同格式各有独立记录。闭源包优先让客户端从厂商下载，仅在取得分发依据后才考虑代存。
3. **发布目录。** 为每条记录保存稳定的应用 ID、多语言名称、发布者、已验证版本、架构、安装配方版本、桌面启动项、按地区分组的 URL、摘要、分发依据和最近验证日期。审核后签发带版本号和有效期的目录；全球与境内入口提供同一份签名内容。客户端内置验证公钥，拒绝被篡改或倒退的目录。
4. **安装。** 首选已验证的 Nix 软件包和可信二进制缓存。有些厂商提供的是 deb、rpm 或 AppImage，需先用受审查的 Nix 配方适配库路径、桌面入口、图标、输入法和文件选择器。若许可只允许厂商直供，则在用户设备上下载固定内容并交给配方。商店仅执行内置支持的安装操作，目录链接无法指定任意命令。
5. **维护。** 定期检查失效链接、内容漂移和新版本。域名超时可切换到同一文件的已审核来源。摘要不符就停用该来源，只接受能通过校验的副本。全部来源失效时暂停该版本的新安装，说明原因，保留已安装应用。新包重新验证通过后再上架。

**两个真实收录样例。** 下表记录的是 2026-11-06 从官网解析出的 x86_64 候选地址。这次核对停在发布来源，安装配方、文件摘要和大陆实网体验留到原型阶段验证。

| 应用 | 厂商发布入口 | 候选下载地址及维护方式 |
| --- | --- | --- |
| 微信 | [微信 Linux 官网](https://linux.weixin.qq.com/) | [厂商 x86_64 deb](https://dldir1v6.qq.com/weixin/Universal/Linux/WeChatLinux_x86_64.deb)。文件名不含版本，每次收录需读取包内版本、固定摘要，并处理原地址被覆盖的情况。 |
| QQ | [QQ Linux 官网](https://im.qq.com/linuxqq/index.shtml) | 官网通过[下载配置](https://cdn-go.cn/qq-web/im.qq.com_new/latest/rainbow/linuxConfig.js)列出[带版本的 amd64 deb](https://qqdl.gtimg.cn/qqfile/QQNTV2/9.9.37/release/816b3c79/QQ_3.2.35_261103_amd64_01.deb)。维护端解析配置中的数据，客户端只读取审核后的记录。 |

GitHub 应用可从发布附件读取文件名、大小和下载地址。Gitee 既可收录上游正式发布的附件，也可作为境内目录候选入口，采用前须验证匿名下载、限流和同步延迟。Nix 软件及依赖还要单独配置可信缓存，应用直链可访问只解决了下载链路的一部分。[GitHub 发布附件接口](https://docs.github.com/en/rest/releases/assets) · [MirrorZ 的 Nix 镜像说明](https://help.mirrors.cernet.edu.cn/nix-channels/)

## 让中国大陆和其他地区都能完成安装

商店首次启动使用随系统附带的目录即可浏览。联网时按区域偏好与实际可达性选择来源，设置中可手动切换“自动 / 中国大陆 / 全球”。语言独立切换，首版提供简体中文和英文，应用 ID、目录格式和安装配方跨语言共用。

大陆验收从空缓存开始，覆盖栖港自身的获取方式、目录与签名、应用本体、运行依赖、字体和图标。测试时使用普通大陆网络，关闭代理，并另测 GitHub 不可达、主镜像超时和中途断网。至少在两家大陆运营商网络各走完一次首装和更新，同时在境外网络走完一次全球路径。记录日期、网络、选用来源、耗时、失败环节和恢复结果。安装介质发布后，把镜像下载和首次开机也纳入同一验收。

## 从软件商店到系统管理

| 阶段 | 交付给用户的能力 | 进入下一阶段的验收条件 |
| --- | --- | --- |
| 1 · 商店原型 | 在预装栖港的测试桌面搜索、安装、打开和卸载应用。先用 VLC 走通，再接入微信和 QQ。 | 三款应用分别完成上述功能检查；重启后可用；重复点安装只产生一个任务；断网重试和校验失败都有明确结果。 |
| 2 · 可公开试用的商店 | 图形化获取入口、中英文目录、境内和全球来源、应用更新及失败恢复。 | 完成两地网络验收。邀请 5 位没有 Linux 经验的用户独立安装并打开指定应用，至少 4 位无需提示完成，全程无需终端。 |
| 3 · 日常系统管理 | 从桌面管理输入法、语言、常用设备和系统更新；预览修改并选择恢复点。 | 在测试机上完成一次设置修改、系统更新和回退；验证用户文件保留，更新失败也能进入可用桌面。 |
| 4 · 首次装机与恢复 | 面向新电脑提供图形安装、首次引导和启动失败后的恢复入口。 | 新用户从下载安装介质到进入桌面并安装首个应用，全程按界面提示完成；擦除磁盘须明确选盘并单独确认。 |

商店先按当前用户维护独立的应用清单，安装成功后才提交新状态。系统管理阶段再引入经过授权的系统服务：界面展示即将更改的设置，后台生成栖港管理的配置模块，先构建验证，再应用并保存上一代。对已有 NixOS 配置先检测接管范围，遇到手写配置冲突就标明冲突项并停止该项更改。系统版本恢复和个人文件备份分别提供入口，并说明各自能恢复的内容。

**下一步。** 先在隔离的 x86_64 KDE 测试环境打通一个可操作原型，观察一位新用户能否自行完成“搜 VLC → 安装 → 打开视频”。同时分别登记微信和 QQ 的版本、分发条件、依赖与下载来源，再按相同入口验证两款软件。首轮交付以这三条可重复的安装记录为准。
